# US-26.0: Dependency and Supply-Chain Security Hardening

*2026-08-04T07:44:53Z*

Stage 26 introduces subscription tiers, payment integration and credit top-up purchase. Shipping real payment flows onto a frontend carrying a live PostCSS XSS / arbitrary-file-read chain is the wrong ordering, so the hardening lands first.

Five things to show:

1. `npm audit --audit-level=high` exits clean
2. the `next` / `postcss` / `sharp` chain is genuinely resolved, not deferred
3. typecheck, lint, test and build still pass on the upgraded tree
4. every action is pinned to an immutable commit SHA
5. CI now fails on a new high-severity finding, so this cannot silently regress

## The gate

`web/` had no CI at all, which is how eleven advisories accumulated unnoticed. The new `web-audit` job:

```bash
awk "/^  web-audit:/{f=1} f" .github/workflows/ci.yml
```

```output
  web-audit:
    name: web npm audit
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1

      - name: Set up Node
        uses: actions/setup-node@820762786026740c76f36085b0efc47a31fe5020 # v7.0.0
        with:
          node-version: "22"
          cache: npm
          cache-dependency-path: web/package-lock.json

      # `npm audit` reads the lockfile and does not need node_modules, so this skips
      # a full install. The advisory database is queried live, so a newly published
      # advisory can fail a PR that changed nothing — that is the point of a gate.
      - name: Audit web dependencies
        working-directory: web
        run: npm audit --audit-level=high

      # A lockfile can be internally inconsistent while `npm ci` still succeeds — an
      # npm version that drops bundled nested entries leaves declared dependencies
      # with no corresponding package entry. This PR shipped exactly that for one
      # commit, and only a reviewer caught it.
      - name: Check the web lockfile is internally consistent
        working-directory: web
        run: npm ls --package-lock-only --all > /dev/null
```

A gate nobody has watched fail is not a gate. Both steps, run against a deliberately broken throwaway copy — never against the real lockfile:


## What is not here

- **The `web-audit` job is not a *required* check.** That is branch protection on `main`, which a PR cannot change. It runs and reports on every PR, but until someone marks it required it cannot block a merge. Worth doing immediately after this lands.
- **`docker-publish.yml` still floats** (`docker/*@v4`/`v6`/`v7`, `actions/checkout@v7`), as do `actions/setup-python` and `astral-sh/setup-uv` in `ci.yml`. The issue scoped pinning to two workflows and I did not widen it — but the same repoint risk applies, and `docker-publish.yml` pushes images. Its own issue.
- **The Python dependency tree is unassessed.** `pip-audit` / `osv-scanner` for the API is explicitly out of scope here.
- **The advisory database is live.** A newly published advisory will fail a PR that changed nothing. That is the gate working as intended, but it will surprise someone the first time.
