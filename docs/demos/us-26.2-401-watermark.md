# US-26.2 / #401 — Free-tier video watermark

*2026-08-09T07:08:41Z*

US-26.2 sells the free tier as **"720p watermarked video"**. PR #399 shipped the resolution half — free accounts get 720p and are refused 1080p/4K — and issue #401 records that the watermark itself was never built. This demo runs the real video job handler against a real MongoDB, real local storage, and real ffmpeg. The only stand-in is the external video provider (no credentials for it exist in this environment): instead of downloading a render over HTTP, it hands back a genuine MP4 that ffmpeg produced locally. Everything downstream of that — tier lookup, watermarking, upload, `Video` record — is the shipping code path.

The mark itself is a committed PNG, generated offline by `scripts/make_watermark.py` from the app icon (`web/app/favicon.ico`) and the wordmark "Cadenza" set in Nunito Sans Bold — the typeface the web app already loads. Rendering it ahead of time means the API host needs no font stack at render time.

```bash
ls -l src/acemusic/assets/watermark.png && uv run python -c "
```

## AC3 — the behaviour of pre-existing videos after an upgrade is decided and documented

Decided by the product owner on the issue: *"Paid users cannot go back and re-generate videos without watermarks. Only videos generated during the period of payment are non-watermarked."* So the mark is decided per render and never revisited — nothing is re-rendered or re-uploaded on an upgrade.

This run renders as a free user, upgrades the account to Pro, and re-reads the stored object.

```bash
uv run python /tmp/claude-1000/-home-frankbria-projects-auto-music-studio/a80b9604-e0f0-4f5e-a84a-caeae52e63c6/scratchpad/demo401.py upgrade
```

```output
video 6a78287b48006ab5f4297d95 rendered while free -> watermarked: True
owner upgraded to pro
stored bytes unchanged by the upgrade : True
still watermarked (not re-rendered)   : True
a NEW render as pro is unmarked       : True
```

The old video keeps its mark; a new render as Pro comes out clean. The decision is written up in the README under **Free-tier video watermark**, which also states the mirror case: a video rendered during a paid period stays unmarked after a downgrade. **AC3 verified.**

## Known limitations

- **The video provider is not live.** No credentials for the external render API exist in this environment, so the provider call is stood in for; everything downstream of it is the shipping code path.
- **ffmpeg is now a hard requirement on the API host for free-tier video.** Absent, free-tier video jobs fail (loudly, by design). CI installs it as of this change; production deployment must too.
- **The mark is not re-checked at delivery.** `GET /videos/{id}/stream` serves the stored bytes. That is the stated policy, not an oversight — a video rendered during a paid period stays unmarked after a downgrade.
- **Multi-process workers can re-claim a long render mid-flight** — pre-existing, widened slightly by the watermarking pass; tracked as #427.
